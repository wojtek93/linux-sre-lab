# MOT-27 — Scrum / Agile / JIRA

## Goal

Be able to briefly explain practical experience working in a Scrum / Agile environment and using tickets and a backlog.

## Practical Scrum Workflow

In my previous teams, Scrum was used as a practical framework for organizing and tracking work.

Typical elements included:

- tickets
- backlog
- sprint planning
- story points
- daily meetings
- blockers
- sprint reviews / retrospectives

The exact Scrum process can differ between teams and companies.

## Backlog and Tickets

Work was represented by tickets stored in a backlog.

The backlog contained tasks that could later be selected for implementation during a sprint.

Tickets could contain:

- task description
- requirements
- priority
- acceptance criteria
- estimation
- implementation status

JIRA can be used to manage and track these tickets.

## Sprint

A sprint is a defined period during which the team works on selected tasks.

During planning, the team selects work from the backlog and decides what should be completed during the sprint.

## Story Points

Story points can be used to estimate the relative complexity or effort of a task.

They are not necessarily a direct measurement of hours.

## Daily Stand-up

Daily meetings provide a short synchronization point for the team.

Typical topics include:

- what has been completed
- what is currently being worked on
- what will be worked on next
- blockers or problems affecting progress

## When a Task Becomes More Complex

If a ticket turns out to be more complex than expected, the important thing is to communicate this early.

Possible actions include:

- discussing the problem with the team
- explaining the additional complexity
- splitting the task
- updating the plan
- moving remaining work to another sprint if appropriate

The exact approach depends on the team's process.

## Interview Answer

> In my previous teams, we used Scrum in a practical way. We worked with tickets in the backlog, estimated tasks, had daily meetings and planned work for the sprint. If a task became more complex than expected, we discussed it with the team and decided how to handle it, for example by splitting it or moving part of the work to the next sprint.

## Useful Vocabulary

- **backlog** — list of planned work
- **ticket** — tracked task or issue
- **sprint** — defined period of work
- **story points** — relative estimation of effort or complexity
- **daily stand-up** — short daily team synchronization
- **blocker** — issue preventing or slowing progress
- **sprint review** — review of sprint results
- **retrospective** — discussion about improving the way the team works

## Key Takeaway

Scrum implementations can differ between organizations.

For an interview, the important point is to explain clearly how the process worked in the actual team and how tickets, planning, communication and blockers were handled.
