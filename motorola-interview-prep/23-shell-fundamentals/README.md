# MOT-23 — Shell Fundamentals

## Objective

Practice essential Bash shell concepts commonly used in Linux administration, automation, troubleshooting and DevOps/SRE work.

Topics covered:

- Exit codes (`$?`)
- Command chaining with `&&`
- Fallback execution with `||`
- Sequential execution with `;`
- Bash signals
- `trap`
- Cleanup on script termination

---

## 1. Exit Codes

Every Linux command returns an exit code after execution.

- `0` — success
- non-zero — error

Example:

```bash
ls /tmp
echo $?
```

Successful command:

```text
0
```

Failed command:

```bash
ls /tmp/no_such_file
echo $?
```

The exit code will be non-zero.

`$?` always contains the exit code of the **previous command**.

---

## 2. AND operator — `&&`

`&&` executes the next command only when the previous command succeeds.

Example:

```bash
mkdir -p /tmp/mot23 && touch /tmp/mot23/test.txt
```

Flow:

```text
mkdir succeeds
      ↓
touch executes
```

If `mkdir` fails, `touch` is not executed.

Another example:

```bash
cd /tmp/mot23 && echo "inside"
```

---

## 3. OR operator — `||`

`||` executes the next command only when the previous command fails.

Example:

```bash
cat /tmp/mot23/missing.txt || echo "file missing"
```

Flow:

```text
cat fails
   ↓
echo "file missing"
```

This pattern is useful for simple error handling.

---

## 4. Sequential execution — `;`

`;` executes the next command regardless of whether the previous command succeeded or failed.

Example:

```bash
ls /tmp/mot23; echo "done"
```

`echo "done"` will always execute.

Difference:

```bash
command1 && command2
```

means:

> Run command2 only if command1 succeeds.

While:

```bash
command1; command2
```

means:

> Run command2 regardless of command1 result.

---

## 5. Combining `&&` and `||`

A common shell pattern:

```bash
cat /etc/passwd && echo "exists" || echo "missing"
```

Another example:

```bash
mkdir /tmp/mot23-final && touch /tmp/mot23-final/ok.txt || echo "failed"
```

Flow:

```text
mkdir
  │
  ├── success → touch
  │               │
  │               └── failure → echo "failed"
  │
  └── failure → echo "failed"
```

This can be useful for short command chains, although more complex scripts should normally use explicit `if` statements for readability.

---

## 6. Checking failure codes

Example:

```bash
ls /tmp/no_such_file || echo $?
```

If `ls` fails, `$?` contains the exit code returned by `ls`.

Example with success:

```bash
ls /tmp && echo $?
```

Output:

```text
0
```

---

## 7. Bash Signals

Linux processes can receive signals.

Important signals:

### SIGINT

Usually generated by:

```text
Ctrl+C
```

Requests interruption of the running process.

### SIGTERM

Standard request to terminate a process.

Example:

```bash
kill <PID>
```

By default, `kill` sends `SIGTERM`.

### SIGKILL

Immediately terminates a process.

Example:

```bash
kill -9 <PID>
```

`SIGKILL` cannot be caught or handled using `trap`.

### SIGHUP

Historically indicates terminal disconnection.

It is also commonly used by services to trigger configuration reloads.

---

## 8. `trap`

`trap` allows a Bash script to execute an action when a specific signal or shell condition occurs.

Example:

```bash
trap cleanup EXIT
```

This means:

> Before the script exits, execute the `cleanup` function.

---

## 9. Cleanup example

```bash
#!/bin/bash

tmpfile=$(mktemp)

cleanup() {
    echo "Cleaning up..."
    rm -f "$tmpfile"
}

trap cleanup EXIT

echo "Temporary file: $tmpfile"
echo "test data" > "$tmpfile"

sleep 30
```

Execution flow:

```text
script starts
      ↓
temporary file created
      ↓
script performs work
      ↓
script starts exiting
      ↓
EXIT trap triggered
      ↓
cleanup()
      ↓
temporary file removed
      ↓
script terminates
```

`EXIT` is a Bash trap condition rather than a Unix signal.

---

## 10. Handling SIGINT and SIGTERM

Signals can also be handled explicitly:

```bash
trap cleanup SIGINT SIGTERM
```

For example:

```bash
#!/bin/bash

tmpfile=$(mktemp)

cleanup() {
    echo "Cleaning up..."
    rm -f "$tmpfile"
}

trap cleanup EXIT
trap 'echo "Termination signal received"; exit 1' SIGINT SIGTERM

echo "Running..."
sleep 30
```

Pressing `Ctrl+C` generates `SIGINT`.

The script handles the signal, exits, and the `EXIT` trap performs cleanup.

## Practical DevOps / SRE Use Cases

These shell mechanisms are useful for:

- automation scripts
- CI/CD jobs
- temporary file cleanup
- deployment scripts
- error handling
- stopping scripts after failed commands
- process termination handling
- operational and maintenance scripts

Typical patterns:

```bash
command && echo "success"
```

```bash
command || echo "failed"
```

```bash
command || exit 1
```

```bash
trap cleanup EXIT
```

---

## Key Takeaways

- `$?` contains the exit code of the previous command.
- Exit code `0` means success.
- Non-zero exit code means failure.
- `&&` executes the next command after success.
- `||` executes the next command after failure.
- `;` executes the next command regardless of the previous result.
- `SIGINT` is commonly generated by `Ctrl+C`.
- `SIGTERM` requests process termination.
- `SIGKILL` cannot be caught by `trap`.
- `trap` allows scripts to react to signals and shell events.
- `trap ... EXIT` is commonly used to guarantee cleanup when a script terminates.
