# PRO-03 Prometheus Installation and First Scrape

## Goal

Install and run Prometheus locally, inspect its web UI, understand the default target configuration, and connect the demo Python application from PRO-02 as a real Prometheus scrape target.

---

## 1. Run Prometheus with Docker

Prometheus was started as a Docker container.

Command:

```bash
docker run -d \
  --name prometheus \
  -p 9090:9090 \
  prom/prometheus
```

Check the running container:

```bash
docker ps
```

Prometheus exposes its web interface on:

```text
http://localhost:9090
```

When Prometheus is running inside a Linux VM, the UI can be opened from the host machine using:

```text
http://<VM_IP>:9090
```

## 8. Custom Prometheus configuration

A custom configuration file was created:

```text
prometheus.yml
```

Configuration:

```yaml
global:
  scrape_interval: 5s

scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets:
          - "localhost:9090"

  - job_name: "demo-app"
    static_configs:
      - targets:
          - "host.docker.internal:8000"
```

---

## 9. `scrape_interval`

The configuration:

```yaml
scrape_interval: 5s
```

means:

```text
Prometheus collects metrics every 5 seconds
```

Mental model:

```text

↓
Prometheus sends HTTP GET
↓

↓

```

---

## 10. Jobs and targets

The configuration contains two jobs.

### Prometheus job

```yaml
- job_name: "prometheus"
```

Target:

```text
localhost:9090
```

This allows Prometheus to monitor itself.

### Demo application job

```yaml
- job_name: "demo-app"
```

Target:

```text
host.docker.internal:8000
```

This allows Prometheus to scrape metrics from the Python demo application.

---

## 11. Why `host.docker.internal` was used

Prometheus runs inside a Docker container.

The Python application runs directly on the Linux VM.

Inside the Prometheus container:

```text
localhost
```

refers to the Prometheus container itself.

It does not refer to the Linux VM.

Therefore the target:

```text
localhost:8000
```

would not reach the Python application.

Instead:

```text
host.docker.internal
```

was mapped to the Docker host.

Mental model:

```text
Prometheus container
↓
host.docker.internal
↓
Linux VM
↓
Python app :8000
```

---

## 12. Docker host mapping

The Prometheus container was started with:

```bash
--add-host=host.docker.internal:host-gateway
```

This creates a mapping inside the container:

```text
host.docker.internal
→ Docker host
```

## 14. Restart Prometheus with custom configuration

The initial container was removed:

```bash
docker rm -f prometheus
```

Prometheus was then started again:

```bash
docker run -d \
  --name prometheus \
  -p 9090:9090 \
  --add-host=host.docker.internal:host-gateway \
  -v "$(pwd)/prometheus.yml:/etc/prometheus/prometheus.yml" \
  prom/prometheus
```

## 18. `rate()`

The following query was tested:

```promql
rate(demo_requests_total[1m])
```

A Counter tells us the total value:

```text
How many events happened in total?
```

`rate()` tells us:

```text
How quickly is the Counter increasing?
```

Mental model:

```text
Counter
→ total number

rate(Counter)
→ events per second
```

---

## 19. Understanding the result

The demo application increments:

```text
demo_requests_total
```

approximately once every 2 seconds.

Therefore the expected rate is around:

```text
0.5
```

Meaning:

```text
0.5 requests per second
```

Because:

```text
1 request / 2 seconds
=
0.5 requests / second
```

## 22. Important terminology

### Target

A target is an endpoint that Prometheus scrapes.

Example:

```text
host.docker.internal:8000
```

### Job

A job groups one or more related scrape targets.

Example:

```text
demo-app
```

### Scrape

A scrape is a single metric collection operation.

Example:

```text
Prometheus
→ HTTP GET /metrics
→ response received
```

### Scrape interval

Time between scrape operations.

Example:

```text
5 seconds
```

## Interview summary

Prometheus uses a pull-based monitoring model. Targets are defined in `prometheus.yml`, and Prometheus periodically scrapes their `/metrics` endpoints.

A scrape configuration is grouped into jobs using `job_name`. Each job contains one or more targets.

The built-in `up` metric indicates whether a target can be successfully scraped.

In this lab, Prometheus was deployed in Docker and configured to scrape both itself and a Python application running on the Docker host.

Because the application was outside the container, `host.docker.internal` together with Docker's `host-gateway` mapping was used to allow Prometheus to reach the host application.

Custom application metrics were then queried using PromQL, including the `rate()` function to calculate the per-second growth of a Counter.
